## 总体结论

当前项目已经不是空壳，后端拥有较多模拟经营核心资产：工程物理计算、底盘/引擎/车型设计、生产库存、市场效用模型、财务贷款、事件、存档和世界生成等都已有实现。但它距离新版 GDD 的核心目标仍有明显差距：GDD 最大卖点是“AI 竞争对手 + AI 高管 + 委托管理”的闭环，而当前 AI 系统主要停留在模型、原型和局部决策代码，尚未稳定接入回合循环。

最需要优先处理的不是继续堆功能，而是先把项目接管稳定下来：前端 TypeScript 构建目前失败，前后端 API/模型字段存在多处错配，很多页面仍硬编码 `companyId = 1`，后端测试环境未配置好 `pytest`。这些问题会阻碍后续任何系统性开发。

## 与新版 GDD 的主要偏离

1. 命名偏离：GDD 使用《工业帝国》(Industrial Empire)，当前应用名、日志和前端仍是 `AutoMogul`。
2. 架构偏离：GDD 规划 `backend/app/`、`services/ai/`、`api/v1/`、`shared/`、`electron/`，当前后端采用 `backend/core`、`backend/logic`、`backend/api/routes` 的实际结构。
3. API 偏离：GDD 使用以 `games/{game_id}` 为根的 REST 风格；当前多为 `/api/v1/game`、`/api/v1/company/{company_id}`、`/api/v1/engineering` 等扁平路由。
4. 状态管理偏离：GDD 提到 Zustand，当前前端使用 Context API。
5. 玩法重心偏离：当前最成熟的是工程/生产细节，新 GDD 最强调的 AI 竞争者和 AI 高管委托系统仍未形成主闭环。
6. 时间单位偏离：GDD 明确以周为单位，代码中已有周度时间，但市场、生产、财务不少逻辑仍以月度语义计算后再粗略换算。
7. 数据单位偏离：公司现金、贷款、成本等在部分代码中混用“百万游戏币”和原始金额，后续需要统一单位规范。

## 当前可运行性风险

### 前端构建失败

执行 `npm run build` 失败，主要问题包括：

- 未使用变量触发 `noUnusedLocals`。
- `process`、`NodeJS.Timeout` 缺少浏览器/Node 类型处理。
- `SaveInfo` 类型与 `MainMenu` 使用字段不一致。
- `EngineeringHub` 中 `SavedEngine` 字面量类型不匹配。
- `ChassisStudio`、`EngineDesigner` 等存在类型字段错配。

### 后端测试无法直接运行

尝试运行后端测试时，本机 Python 与 Codex bundled Python 均缺少 `pytest`。后续需要先建立明确的后端虚拟环境与测试命令，再谈测试覆盖率。

### 前后端字段明显错配

例如 `backend/api/routes/staff.py` 和 `backend/api/routes/company.py` 仍引用 `Staff.name`、`salary`、`loyalty`、`skill_technical` 等旧字段，而当前 `Staff` 模型使用 `first_name`、`last_name`、`annual_salary`、`current_loyalty`、`skill_engineering` 等字段。这类错配会导致对应 API 运行时失败。

## 后续开发优先级摘要

详细计划已存放在 [docs/DEVELOPMENT_PLAN_CN.md](docs/DEVELOPMENT_PLAN_CN.md)。

1. `P0` 接管稳定：修复前端构建、后端测试环境、API/模型字段错配、硬编码公司 ID。
2. `P1` 打通核心经营闭环：回合循环中接入生产、市场、销售历史、财务和报表。
3. `P1` 接入 AI 竞争对手：让 AI 决策真正执行定价、营销、研发、扩张，并引入组织惯性。
4. `P2` 实现 AI 高管委托：KPI、管理哲学、自然语言指令、报告和自动执行。
5. `P2` 强化市场与品牌：消费者效用、区域偏好、营销、品牌认知与销量反馈闭环。
6. `P3` 扩展深层经营：供应链危机、工会、法规合规、召回、M&A、股东与融资。
7. `P4` 完成体验层：历史回放、任务模式、Electron 打包、教程与本地化。
