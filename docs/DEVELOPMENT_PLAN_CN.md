# 后续开发计划（按优先级）

本计划以新版 GDD 的目标为准，同时尊重当前代码已经形成的工程/生产/市场基础。目标不是推倒重来，而是先把已有系统接成可玩的经营闭环，再补齐 GDD 的差异化卖点。

## P0：接管稳定期

### 1. 修复前端构建

目标：`cd frontend && npm run build` 必须通过。

工作项：

- 清理未使用变量或调整 `tsconfig` 策略。
- 处理 `process`、`NodeJS.Timeout` 等浏览器项目中的类型问题，优先改为 `ReturnType<typeof setTimeout>` 或显式 Vite 环境变量。
- 对齐 `SaveInfo`、`SavedEngine`、底盘计算结果、工程组件列表等类型。
- 统一 `factoryService`、`engineeringService`、`executiveService` 的返回类型。

验收标准：

- `npm run build` 通过。
- `npm run lint` 无关键错误。
- 主菜单、新游戏、加载存档、进入游戏主界面不出现白屏。

### 2. 建立后端测试环境

目标：后端测试可在固定命令下运行。

工作项：

- 建议创建 `.venv`，安装 `backend/requirements.txt`。
- 明确 Python 版本，优先使用依赖兼容性更稳的 3.11 或 3.12。
- 整理测试入口，区分单元测试、集成测试和会修改数据库的脚本测试。
- 为测试数据库设置隔离路径，避免污染真实存档。

验收标准：

- `python -m pytest backend/test_data_driven.py backend/test_unlocked_components.py -q` 可运行。
- 会修改数据库的测试有明确说明或独立测试库。

### 3. 修复 API 与模型字段错配

目标：当前已暴露的 API 不再引用不存在的字段。

重点文件：

- `backend/api/routes/staff.py`
- `backend/api/routes/company.py`
- `frontend/src/services/executiveService.ts`
- `frontend/src/pages/executive/ExecutiveRoom.tsx`

工作项：

- 将旧字段 `name/salary/loyalty/skill_technical` 等迁移到 `Staff.full_name/annual_salary/current_loyalty/skill_engineering` 等当前模型字段。
- 删除重复或冲突的人事 API，保留一套真实可用的接口。
- 前端高管页面改用真实接口响应。

验收标准：

- 高管列表、招聘、解雇接口可用。
- Executive 页面不再依赖不存在字段。

### 4. 移除前端硬编码公司 ID

目标：所有页面从游戏上下文读取玩家公司与当前游戏。

工作项：

- 在 `GameContext` 中保存 `game_id`、`player_company_id`、当前存档信息。
- 替换工程、工厂、市场、研发、报表、高管页面中的 `companyId = 1`。
- 后端 `game/state` 返回玩家公司 ID 和基础公司摘要。

验收标准：

- 新建不同公司名的存档后，前端所有模块都操作该玩家公司。

## P1：打通核心经营闭环

### 5. 让回合循环真正结算生产

目标：生产线分配之后，每周自动产出并进入库存。

工作项：

- 在 `GameLoopManager._phase_production` 接入 `ProductionManager`。
- 将生产线月产能转换为周产能，并考虑重整、工厂效率、材料库存、熟悉度。
- 零部件生产、整车装配、材料消耗、成品车库存写入统一库存。
- 供应商合约交付结果必须真正增加材料库存。

验收标准：

- 分配生产线后推进回合，库存和公司月度产量变化。
- 材料不足时生产线降产或停产，并生成事件。

### 6. 让市场销售影响财务和库存

目标：市场模拟结果不只是返回数据，而是改变游戏状态。

工作项：

- `MarketSimulator` 销售新车时扣减可售库存。
- 写入 `SalesHistory`，更新 `Company.monthly_revenue`、`monthly_units_sold`、市场份额。
- 计算制造成本、毛利、营销影响。
- 未满足需求转入二手车或流失，并记录原因。

验收标准：

- 推进回合后，销量、收入、库存、历史图表同步变化。
- 市场页展示真实区域销量和市场份额。

### 7. 完成财务报表闭环

目标：经营动作最终反映到现金、利润、资产负债和月报。

工作项：

- 统一金额单位。
- 整合制造成本、材料成本、人工、营销、研发、贷款利息。
- `FinancialHistory` 记录真实快照。
- 月报弹窗和报表页接真实 API。

验收标准：

- 每月结束生成可信月报。
- 报表页能解释现金变化来源。

### 8. 修正 API 形态或建立兼容层

目标：让前后端和 GDD 的接口规划不再互相打架。

建议路线：

- 短期保留当前 `/api/v1/game` 等接口。
- 新增一个薄兼容层，逐步向 GDD 的 `/api/v1/games/{game_id}/...` 迁移。
- 文档中明确哪些接口是 legacy，哪些是 future-facing。

验收标准：

- Swagger 文档中接口命名清晰。
- 前端服务层不直接拼混乱路径。

## P1：AI 竞争对手主闭环

### 9. 接入 AI 决策系统

目标：AI 公司每回合能做真实动作。

工作项：

- 在 `GameLoopManager._phase_ai_decisions` 调用 `run_ai_turn_for_company`。
- 从 `Company.ai_personality_traits` 读取人格，而不是随机状态。
- AI 决策要基于真实现金、销量、市场份额、产能利用率。
- 决策执行器实现定价、营销、研发、扩张、成本削减。

验收标准：

- AI 公司会创建营销活动、调整售价、启动研发、扩建工厂。
- AI 行为写入事件日志，可在前端 ticker 看到。

### 10. 补齐 CEO 五维人格与组织惯性

目标：实现 GDD 的核心 AI 差异化。

工作项：

- 将 `foresight` 加入 `CEOPersonality` 和 `Company.ai_personality_traits`。
- 公司规模决定决策延迟：小公司 1-2 周，中型 2-4 周，大型 4-8 周，巨头 8-16 周。
- AI 决策进入队列，到期再执行。
- 远见影响技术趋势预测、进入新能源或新地区的时机。

验收标准：

- 不同性格 AI 呈现可观察的长期差异。
- 巨头反应慢，小公司反应快。

## P2：AI 高管与委托管理

### 11. 高管 KPI 与管理哲学

目标：玩家可通过高层目标影响公司运营，而不是只手动点按钮。

工作项：

- 为 CTO/CFO/COO/CMO/CHRO 定义 KPI 类型。
- 管理哲学影响 AI 高管自动决策权重，如质量优先、成本领先、创新领先。
- 高管能力、士气、忠诚度影响执行质量和风险。

验收标准：

- 玩家设置 KPI 后，高管能生成行动计划。
- KPI 完成度影响高管评价、士气和留任风险。

### 12. 自然语言指令执行管线

目标：让 GDD 示例“开发一款经济型轿车用于亚洲市场”真正可用。

工作项：

- 为 `DirectiveParser` 增加 API。
- 前端高管/研发页面提供指令输入框。
- 解析结果生成 `Directive`，由对应高管执行。
- 低置信度或缺失参数时返回澄清问题。

验收标准：

- 输入设计、生产、营销、研发、财务类指令后能生成结构化计划。
- 指令进度可跟踪，可完成或失败。

### 13. CEO 变更与高管流动

目标：AI 公司和玩家公司都出现有意义的人事变化。

工作项：

- 年龄退休、绩效解雇、董事会冲突、跳槽挖角。
- 高管离职影响公司战略和正在执行的项目。
- 竞争对手可挖角玩家高管，玩家也可挖角对手人才。

验收标准：

- AI CEO 更替后，公司策略出现可观察变化。
- 高忠诚/低忠诚高管行为不同。

## P2：市场、品牌与事件深度

### 14. 市场效用模型产品化

目标：把已有 Logit 模型变成玩家能理解和利用的系统。

工作项：

- 区域消费者桶初始化和长期演化。
- 车型属性、价格、品牌、分销、营销共同影响购买概率。
- 前端展示“为什么卖得好/不好”的解释。

验收标准：

- 市场页不再是占位数据。
- 玩家调整定价和营销后，下回合销售有合理变化。

### 15. 品牌系统闭环

目标：品牌五维形象随经营历史变化。

工作项：

- 销售质量、可靠性、召回、赛事、营销、技术突破影响品牌。
- 地区品牌认知和全球公司声望互相影响。
- 品牌影响定价权和消费者效用。

验收标准：

- 高质量长期销售能提升可靠性品牌。
- 召回会打击可靠性和销量。

### 16. 事件内容与长期效果

目标：实现 GDD 的小/中/大事件层级。

工作项：

- 小事件：原材料波动、质量投诉。
- 中事件：技术突破、工会谈判、新竞争者。
- 大事件：石油危机、金融风暴、大规模召回。
- 事件效果进入市场、生产、财务和品牌系统。

验收标准：

- 事件不是新闻文本，而会改变经营约束。

## P3：深层经营系统

### 17. 供应链危机与供应商

目标：让供应链成为经营决策，而不是静态采购。

工作项：

- 多源供应、安全库存、合同优先级、供应商破产。
- 自然灾害、地缘政治、芯片短缺、电池瓶颈。
- AI 采购策略从模拟计划改为读取真实生产计划。

验收标准：

- 单一供应商依赖会在危机中造成停产。
- 安全库存和多源供应能缓冲危机。

### 18. 法规、合规和召回

目标：地区市场准入和产品质量产生长期压力。

工作项：

- 排放、安全、燃油经济性法规按年份生效。
- 车型上市前进行合规审核。
- 不合规可罚款或禁售。
- 缺陷发现、召回决策、召回执行、品牌影响。

验收标准：

- 老车型在新法规下可能失去市场准入。
- 主动召回与隐瞒问题有不同风险收益。

### 19. 工会与员工系统

目标：补齐 GDD 的执行层员工与工会机制。

工作项：

- 地区工资水平、工作条件、满意度。
- 工会组织率、谈判、罢工概率。
- 罢工期间产能停摆，需谈判解决。

验收标准：

- 低工资/高压力策略短期省钱，长期增加罢工风险。

### 20. M&A、股东与资本市场

目标：实现 GDD 的公司金融扩展。

工作项：

- 股票发行、回购、分红、股东结构。
- 收购目标、估值、并购、反收购。
- AI 公司可参与并购。

验收标准：

- 玩家可通过资本市场扩张或缓解现金流危机。

## P4：体验、内容与发布

### 21. 历史回放

目标：让长期经营有可回顾的史诗感。

工作项：

- 时间线视图。
- 销量、市值、利润历史曲线。
- 里程碑事件。
- 车型生命周期回放。

验收标准：

- 玩家能回看公司从第一款车到巨头的历程。

### 22. 游戏模式与任务

目标：补齐 GDD 的开放沙盒、现实模式、任务模式。

工作项：

- 沙盒无结束时间。
- 现实模式 1950-2030。
- 历史事件挑战任务。

验收标准：

- 新游戏菜单能选择模式，规则和目标不同。

### 23. Electron 与发布包

目标：形成可交付桌面版本。

工作项：

- 建立 `electron/` 主进程和 preload。
- 打包前后端启动流程。
- 存档路径、日志路径和崩溃报告策略。

验收标准：

- Windows 本地可一键启动游戏。

### 24. 文档与开发纪律

目标：让项目不再依赖单次 AI 会话记忆。

工作项：

- 写清架构文档、API 文档、数据单位规范。
- 建立任务看板或里程碑。
- 每个核心系统补最小测试。

验收标准：

- 新开发者可通过 README 和 docs 独立启动、测试、定位系统。
